# Сценарий финальной демонстрации

27.09.2026. Проверенный формат: локальная демонстрация через API и исполняемый скрипт.
Ручная демонстрация браузерного интерфейса требует репетиции по M01–M15 из TESTING_CHECKLIST.md: в данной среде управляемый браузер недоступен.

## Подготовка

1. Запустить Docker Desktop.
2. Из корня проекта выполнить `docker compose up -d --build`.
3. Проверить http://localhost:8000/health — status=ok, real_calls=false.
4. Интерфейс: http://localhost:5173. API-документация: http://localhost:8000/docs.
5. Для повторного контроля выполнить:

```powershell
docker compose exec -T -e TEST_API_URL=http://localhost:8000/api backend pytest -q
```

Ожидается 25 passed. Тесты создают записи QA; их не следует выбирать для показа.

Демо-учётные записи:

| Роль | Логин | Пароль |
|---|---|---|
| Администратор | admin@example.local | Admin123! |
| Преподаватель | teacher@example.local | Teacher123! |
| Обучающийся | student@example.local | Student123! |

## Проверенный показ, 5–7 минут

Исполняемый сценарий:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/demo.ps1
```

Параметр ExecutionPolicy действует только на этот процесс, без изменения системной политики.
Каждый запуск создаёт новый сценарий и занятие с уникальными идентификаторами.

| Этап | Что показываем / говорим | Проверяемый результат |
|---|---|---|
| 1, 30 сек | «Это локальный учебный тренажёр; реальные экстренные вызовы не принимаются» | /health: LOCAL_TRAINING_ONLY, real_calls=false |
| 2, 45 сек | Вход под ADMIN, TEACHER, STUDENT | Три строки «Вход подтверждён» |
| 3, 1 мин | Преподаватель генерирует mock AI-кандидат категории ДТП, сохраняет, подтверждает публикацией | Сценарий имеет собственный id и published=true |
| 4, 45 сек | Создание занятия с этим сценарием и запуск | DRAFT → RUNNING |
| 5, 1 мин | Обучающийся принимает вызов и заполняет категорию, статус, службы, теги и комментарий | Журнал из пяти действий |
| 6, 45 сек | Завершение карточки и расчёт сервером | 7/7, без ошибок; время у автоматического скрипта обычно 0–1 сек |
| 7, 1 мин | Получение результата преподавателем, экспорт CSV и PDF | docs/demo-output/assessment.csv и assessment.pdf |
| 8, 30 сек | Завершение занятия | RUNNING → COMPLETED; повторный старт запрещён |

Проверенный итог запуска: три роли авторизованы, карточка 7/7, оба отчёта скачаны, занятие завершено.
Этот скрипт демонстрирует серверный цикл, но не заменяет проверку пользовательского интерфейса.

## Репетиция браузерного показа — после ручной проверки

Использовать обычное и приватное окно, чтобы роли не разделяли localStorage.

1. В обычном окне войти преподавателем.
2. Выбрать ДТП → «Сгенерировать AI». Проверить сообщение, при желании изменить название/текст.
3. «Сохранить черновик» → «Опубликовать».
4. В блоке «Занятие» выбрать именно этот новый сценарий, задать понятное название, нажать «Создать занятие» → «Запустить».
5. В приватном окне войти обучающимся, нажать «Обновить занятия» → «Принять учебный вызов».
6. Выбрать ДТП, ПРИНЯТО, службу ДДС и все три тега. Ввести «Сообщение принято, информация зафиксирована.»
7. Нажать «Сохранить комментарий». Перезагрузить страницу и проверить сохранённые поля и непрерывность таймера.
8. В пределах 120 секунд нажать «Завершить карточку». Ожидается 7/7.
9. У преподавателя нажать «Обновить данные», найти соответствующий результат, скачать CSV/PDF.
10. Нажать «Завершить занятие». Выйти. При необходимости отдельно показать вход администратора.

До заполнения ручного чек-листа эту последовательность следует считать **планом репетиции**, а не подтверждённым финальным UI-показом.

Не включать в демонстрацию реальные SIP/RTU, внешнюю AI-модель, мониторинг через WebSocket, пользовательские справочники после импорта, формы управления пользователями и группами: эти функции не подтверждены как готовые пользовательские сценарии.

## Если что-то пошло не так

- Нет занятия у обучающегося: проверить RUNNING, затем «Обновить занятия».
- «Все сценарии занятия пройдены»: создать новое занятие; повторно завершённое занятие не запускается.
- Не завершается занятие: сначала завершить активную карточку.
- Не работает backend: `docker compose logs --tail 100 backend`.
- Не менять данные/схему БД во время демонстрации. Пользоваться новым отдельным занятием.
