## Как открыть

1. Открыть http://localhost:5173 и обновить страницу после пересборки.
2. Войти преподавателем: teacher@example.local / Teacher123!
3. В блоке «Классификатор ЕКП» выбрать версию с исходным названием файла без префикса QA.
4. Искать по коду или части названия. Например: «ДТП без пострадавших» или 2010000.
5. Нажать «Открыть» у нужной строки: появятся признаки, код главной службы, правила по службам, условия и исходные ячейки.
6. Раскрыть «Все исходные ячейки строки» для проверки A:CL.
7. Фильтр по службе означает наличие записи в матрице этой службы. Он не доказывает, что условие подключения выполнено.

Новый файл: выбрать XLSX → «Проверить файл» → изучить ошибки и замечания → «Сохранить версию в справочник».
Сохранение доступно автору импорта и администратору. Обучающийся не имеет доступа к импорту и эталонным данным.
Проверка файла создаёт черновик STAGED; до подтверждения он не попадает в нормализованный справочник.
Повторное подтверждение одной версии не создаёт дубликаты.
Разные загрузки не перезаписывают прежние версии.

## Что сохраняется

В classifier_imports добавлены формат, SHA-256, версия парсера, структура листов, каталог служб, статистика и замечания. Исходные значения всех столбцов каждой строки и формулы сохраняются в rows; бинарный XLSX в БД не хранится.

В classifier_entries сохраняются отдельные записи происшествий, привязанные к версии, листу и номеру строки:
номер E, итоговый тип K, группа, признаки G:J, тип ЕКП L, код сценария M, код главной службы N и матрица правил O:CL.

Каждое правило содержит:
- исходную ячейку;
- службу и канал, если он указан в шапке;
- исходный текст условия;
- классификацию службы либо явный NO_RESPONSE;
- структурированное условие и признак необходимости уточнения.

Типы условий: always (без дополнительного условия в этой ячейке), flag (явно указанный признак), all_false (не выбраны дополнительные признаки данной службы), unresolved.
Это описание матрицы источника, а не реализованный движок автоматической диспетчеризации. Коды сценариев реагирования сохраняются как коды и не интерпретируются вымышленными алгоритмами.

## Замечания к источнику

38 замечаний состоят из:
- 30 строк без заданного сценария M, включая значение «без сценария»;
- 7 заголовков условий для уточнения: V, AI, AJ, AQ, AS, AT, CE;
- 1 предупреждения о наличии пожаров/задымлений при слове «искл» в имени файла.

В частности, не додуманы сокращения «>5 чел / ОД», «пеш», «ав», внешний «объект из перечня» и неоднозначное «Правонарушение или Пострадавшие не выбран». Зависящие от них условия «признак не выбран» также помечены для уточнения.

«Нет реагирования» хранится как отрицательное правило и не превращается в назначение службы.
Пропущенный M не заполняется значением соседней строки.
Пожарные строки сохранены и отмечены предупреждением, поскольку имя файла не является достаточным основанием для удаления данных.

## Повторный запуск тестов

Из корня проекта:

```powershell
docker compose up -d --build
docker compose cp tmp/source-review/classifier.xlsx backend:/tmp/classifier.xlsx
docker compose exec -T -e EKP_SOURCE_PATH=/tmp/classifier.xlsx -e TEST_API_URL=http://localhost:8000/api backend pytest -q
```

tmp/source-review/classifier.xlsx — локальная копия предоставленного пользователем файла. Если она отсутствует, скопируйте исходный XLSX в этот путь либо используйте другой путь в docker compose cp.
Без EKP_SOURCE_PATH два теста реального исходника пропускаются; без TEST_API_URL пропускаются интеграционные тесты. Это не эквивалент полного прогона.

Повторяемый импорт через API:
```powershell
docker compose exec -T backend python -m app.import_classifier /tmp/classifier.xlsx --filename classifier.xlsx
```
CLI использует демо-учётную запись преподавателя; IMPORT_EMAIL и IMPORT_PASSWORD позволяют задать другую. Токен не выводится. При совпадении имени файла и SHA-256 уже сохранённая версия используется повторно.
