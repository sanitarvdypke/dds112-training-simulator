# Этап 3 — список происшествий, карточка ДДС и история

Дата: 29.09.2026. Этап реализован и проверен автоматизированно. Ручная проверка интерфейса остаётся открытой: список доступных браузеров пуст, Computer Use возвращает ошибку подключения native pipe. Сборка интерфейса не заменяет ручной прогон.

## Что изменилось

В кабинете ученика теперь есть список происшествий: учебный номер, занятие, дата добавления, время получения, тип, адрес, код ЕКП и текущий статус службы. Поиск работает по этим текстовым данным; фильтры показывают новые, активные и завершённые карточки. Список обновляется кнопкой «Обновить список».

Можно открыть конкретную карточку, а не только следующую по порядку. Новые строки видны только адресату с учётом учебной группы. В одном занятии одновременно обрабатывается одна карточка; вторую можно получить после завершения активной. В разных занятиях ограничение независимое. Два одновременных запроса одной карточки возвращают один ID.

Исходный блок 112 доступен только для чтения: тип, код ЕКП, адрес, сообщение, сведения и признаки ЕКП, получатели, время получения. Отдельно сохраняются учебные поля обработки ДДС: подразделение/бригада, ответственный, принятые меры, результат работ. Это реализация полей для обучения, а не утверждение о полном воспроизведении всех полей промышленной системы 112. Карта и отсутствующие в исходных данных координаты не добавлялись.

Журнал содержит добавление карточки в занятие, получение службой, каждую смену статуса с комментарием, отдельные комментарии, версии сведений ДДС и завершение практики. Для действий сохраняются серверное время и последовательный номер; отображаются оператор и служба, закреплённая при получении. Смена профиля после завершения не меняет принадлежность старой истории.

Статусы: ПРИНЯТО, НЕ ПРИНЯТО, НАЧАЛО РЕАГИРОВАНИЯ, ПРИБЫТИЕ, ПРОВЕДЕНИЕ РАБОТ, ОТКАЗ ОТ ВЫПОЛНЕНИЯ РАБОТ, РАБОТЫ ЗАВЕРШЕНЫ. Сохранение статуса выполняется отдельной кнопкой, вместе с комментарием. Список допустимых значений проверяет сервер. Обязательный порядок переходов не выдумывается по скриншотам: эталоны последовательности и интервалы относятся к этапу 4.

После завершения доступен просмотр карточки, истории и результата. Изменения запрещены сервером. Просмотр списка и архива не запускает новую попытку и не меняет таймер. В интерфейсе таймер завершённой карточки остановлен на серверном времени завершения. Для активной карточки время по-прежнему отсчитывается от получения, а дата «Добавлена» соответствует запуску занятия.

При обновлении страницы восстанавливается выбранная карточка по её ID через GET, без повторного получения. При выходе к списку или обновлении открытой карточки несохранённые поля нужно сохранить либо явно сбросить. Для перезагрузки страницы с несохранёнными данными установлен стандартный beforeunload. Несохранённые данные не сохраняются на сервер автоматически.

Полная оценка последовательности, обязательных переходов и временных интервалов ещё не реализована. Изменение оценки в этом этапе устраняет потерю принятия при последующем реагировании. Дополнительные допустимые статусы и сведения ДДС не считаются ошибкой только из-за их отсутствия в прежнем простом эталоне. Базовый эталон остаётся: событие ПРИНЯТО — 2 балла, непустой отдельный комментарий — 1 балл. Комментарий к статусу хранится в этом событии и пока не заменяет отдельный комментарий эталона.

## Подготовленная демонстрация

Две новые карточки уже созданы, опубликованы и доступны demo-ученику. Они оставлены непройденными. Норматив этого демонстрационного занятия — 600 секунд на карточку, чтобы успеть показать историю. Исходный пункт ЕКП — 2010000, строка 277 исходного импорта. Учебное пояснение преподавателя по неоднозначной ячейке V277 сохранено из этапа 2; оно не объявляется полной расшифровкой алгоритма 2_4.

1. Открыть http://localhost:5173, обновить страницу. Войти **student@example.local / Student123!**.
2. В списке происшествий найти **«Этап 3 — карточка ДДС и история обработки»**. Если открылась прежняя карточка — нажать «К списку происшествий». Новые карточки имеют адреса «Учебный адрес: улица Тренировочная, 1» и «… 2».
3. Получить карточку с адресом 2. Просмотреть заполненный исходный блок 112 и текущую службу МВД.
4. Выбрать ПРИНЯТО, ввести комментарий к статусу, нажать «Зафиксировать статус».
5. Заполнить подразделение, ответственного и принятые меры; нажать «Сохранить сведения ДДС».
6. Последовательно зафиксировать НАЧАЛО РЕАГИРОВАНИЯ → ПРИБЫТИЕ → ПРОВЕДЕНИЕ РАБОТ → РАБОТЫ ЗАВЕРШЕНЫ. Показать отдельные строки журнала с временем.
7. Заполнить результат работ и сохранить. В блоке «Комментарий диспетчера» добавить отдельную запись «Информация принята, обработка завершена.».
8. Обновить страницу после сохранения: выбранная карточка, поля и история восстановятся, начало таймера не изменится.
9. Нажать «Завершить практику по карточке». Ожидается 3/3; превышение норматива, если оно было, фиксируется отдельно.
10. Вернуться к списку, включить фильтр «Завершённые», открыть карточку для просмотра. Убедиться, что новых действий больше нет. Новая карточка с адресом 1 остаётся доступной для следующей попытки.

Это сценарий для ручного показа на основе проверенных API; сам UI-сценарий нужно пройти вручную перед финальной демонстрацией. Идентификаторы подготовленных объектов: [stage3-demo-state.json](stage3-demo-state.json).
